# 出入库核心流程说明

## 一、入库流程（Inbound）

### 1. 前端表单提交

**文件路径**: `frontend/src/views/inventory/Inbound.vue`

#### 前端数据结构
```javascript
form: {
  serialNo: '',        // 入库单号（自动生成）
  material: { id: null }, // 物资ID
  quantity: 1,         // 入库数量
  price: 0,            // 入库单价
  supplier: { id: null }, // 供应商ID
  remark: ''           // 备注
}
```

#### 前端校验
1. **必填校验**: 提交时检查 `material.id` 是否存在，未选择物资则提示「请选择物资」并阻止提交
2. **数据自动填充**: 选择物资后自动回填单价（`price`）和供应商（`supplier.id`）
3. **单号生成**: 格式为 `IN-yyyyMMddHHmmss`，前端自动生成并禁用编辑

#### 提交逻辑
```javascript
const handleSubmit = async () => {
  // 1. 校验物资是否已选择
  if (!form.value.material.id) {
    ElMessage.error('请选择物资');
    return;
  }
  
  // 2. 构造请求体（供应商未选则设为 null）
  const payload = { ...form.value };
  if (!payload.supplier.id) payload.supplier = null;
  
  // 3. 调用后端 API
  const res = await axios.post('/inventory/inbound', payload);
  if (res.code === 200) {
    ElMessage.success('入库成功');
    // 4. 重置表单并重新生成单号
    form.value = { ... };
    generateSerialNo();
  }
};
```

### 2. 后端 Controller 层

**文件路径**: `backend/src/main/java/com/warehouse/controller/InventoryController.java`

- 接收 JSON 格式的 `InboundRecord` 对象
- 直接委托给 `InventoryService.processInbound()` 处理
- 返回统一的 `ApiResponse` 包装结果

---

### 3. 后端 Service 层（核心处理逻辑）

**文件路径**: `backend/src/main/java/com/warehouse/service/InventoryService.java`

```java
@Transactional
public InboundRecord processInbound(InboundRecord record) {
    // 步骤1: 设置入库时间为当前时间
    record.setInboundTime(LocalDateTime.now());
    
    // 步骤2: 查询物资信息（校验物资是否存在）
    Material material = materialRepository.findById(record.getMaterial().getId())
            .orElseThrow(() -> new RuntimeException("Material not found"));
    
    // 步骤3: 更新库存（累加）
    material.setStockQuantity(material.getStockQuantity() + record.getQuantity());
    materialRepository.save(material);
    
    // 步骤4: 关联完整物资对象并保存入库记录
    record.setMaterial(material);
    return inboundRecordRepository.save(record);
}
```

#### 关键说明
- **事务注解 `@Transactional`**: 整个入库操作在一个事务中执行，库存更新和记录保存要么同时成功，要么同时回滚
- **物资存在性校验**: 通过 `materialRepository.findById()` 查询，不存在则抛出 `RuntimeException`
- **库存更新方式**: 直接在 `Material` 实体的 `stockQuantity` 字段上累加，不涉及复杂的库存计算

---

### 4. 数据持久化（Entity 定义）

**文件路径**: `backend/src/main/java/com/warehouse/entity/InboundRecord.java`

```java
@Entity
@Table(name = "inbound_records")
public class InboundRecord {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(unique = true, nullable = false)
    private String serialNo;        // 入库单号（唯一）
    
    @Column(nullable = false)
    private LocalDateTime inboundTime; // 入库时间
    
    @Column(nullable = false)
    private Integer quantity;       // 入库数量
    
    private Double price;           // 入库单价
    
    @ManyToOne
    @JoinColumn(name = "material_id", nullable = false)
    private Material material;      // 关联物资（外键）
    
    @ManyToOne
    @JoinColumn(name = "supplier_id")
    private Supplier supplier;      // 关联供应商（外键，可为空）
    
    private String remark;          // 备注
}
```

## 二、出库流程（Outbound）及库存不足处理

### 1. 前端表单提交

**文件路径**: `frontend/src/views/inventory/Outbound.vue`

#### 前端数据结构
```javascript
form: {
  serialNo: '',        // 出库单号（自动生成）
  material: { id: null }, // 物资ID
  quantity: 1,         // 出库数量
  department: '',      // 领用部门
  remark: ''           // 备注
}
```

#### 前端校验（两道防线）

**第一道防线 - 选择物资时显示库存**
```javascript
const handleMaterialChange = (val: number) => {
  const material = materials.value.find(m => m.id === val);
  if (material) {
    currentStock.value = material.stockQuantity || 0;
  }
};
```
- 选择物资后立即显示当前库存（`currentStock`）
- 下拉选项中直接展示库存：`${item.code} - ${item.name} (库存: ${item.stockQuantity})`
- 数量输入框设置 `:max="currentStock > 0 ? currentStock : 1"` 限制最大可选值

**第二道防线 - 提交时校验**
```javascript
const handleSubmit = async () => {
  if (!form.value.material.id) {
    ElMessage.error('请选择物资');
    return;
  }
  // 库存不足前端拦截
  if (form.value.quantity > currentStock.value) {
    ElMessage.error(`库存不足，当前库存: ${currentStock.value}`);
    return;
  }
  
  const res = await axios.post('/inventory/outbound', form.value);
  if (res.code === 200) {
    ElMessage.success('出库成功');
    // 重置表单 + 刷新物资列表
    fetchMaterials();
  }
};
```

### 2. 后端 Service 层（库存不足的后端校验）

**文件路径**: `backend/src/main/java/com/warehouse/service/InventoryService.java`

```java
@Transactional
public OutboundRecord processOutbound(OutboundRecord record) {
    // 步骤1: 设置出库时间
    record.setOutboundTime(LocalDateTime.now());
    
    // 步骤2: 查询物资
    Material material = materialRepository.findById(record.getMaterial().getId())
            .orElseThrow(() -> new RuntimeException("Material not found"));
    
    // 步骤3: 库存不足校验（后端兜底）
    if (material.getStockQuantity() < record.getQuantity()) {
        throw new RuntimeException("Insufficient stock! Current: " + material.getStockQuantity());
    }
    
    // 步骤4: 扣减库存
    material.setStockQuantity(material.getStockQuantity() - record.getQuantity());
    materialRepository.save(material);
    
    // 步骤5: 保存出库记录
    record.setMaterial(material);
    return outboundRecordRepository.save(record);
}
```

#### 库存不足的处理机制

| 阶段 | 校验位置 | 校验逻辑 | 异常处理 |
|------|---------|---------|---------|
| 前端展示 | `Outbound.vue:32-37` | 选择物资时显示库存，输入框限制 max | 仅展示，不阻止 |
| 前端提交 | `Outbound.vue:44-47` | `quantity > currentStock` 时拦截请求 | `ElMessage.error` 提示，不发请求 |
| 后端校验 | `InventoryService.java:46-48` | `stockQuantity < quantity` 时抛出异常 | `RuntimeException` → 全局异常处理 → 返回 400 错误 |

#### 全局异常处理

**文件路径**: `backend/src/main/java/com/warehouse/exception/GlobalExceptionHandler.java`

```java
@ExceptionHandler(RuntimeException.class)
@ResponseStatus(HttpStatus.BAD_REQUEST)
public ApiResponse<String> handleRuntimeException(RuntimeException e) {
    log.error("Runtime exception: {}", e.getMessage());
    return ApiResponse.error(400, e.getMessage());
}
```

- 后端抛出的 `RuntimeException` 会被捕获，包装成 `ApiResponse.error(400, 消息)` 返回
- HTTP 状态码为 `400 BAD_REQUEST`

## 三、ECharts 统计图数据聚合逻辑

**文件路径**: `frontend/src/views/report/StockReport.vue`

### 1. 数据来源

所有图表数据均来自同一个 API：
```javascript
const res = await axios.get('/materials');
if (res.code === 200) {
  materials.value = res.data;  // 获取所有物资列表
```

**API 响应格式**: 返回 `Material` 实体数组，每条数据包含：
```javascript

  id, code, name, spec, unit, price,
  category: { id, name },     // 关联分类
```

### 2. 四个统计卡片（Vue computed 属性）

## 四、核心数据实体关系

```
Material (物资主表)
  ├── id (PK)
  ├── code, name, spec, unit, price
  ├── category_id (FK → Category)
  ├── supplier_id (FK → Supplier)
  ├── stockQuantity (当前库存，出入库操作直接更新此字段)
  └── alertThreshold (预警阈值)

InboundRecord (入库记录表)
  ├── id (PK)
  ├── serialNo (入库单号，唯一)
  ├── inboundTime
  ├── quantity
  ├── price (入库单价)
  ├── material_id (FK → Material, 非空)
  ├── supplier_id (FK → Supplier, 可空)
  └── remark

OutboundRecord (出库记录表)
  ├── id (PK)
  ├── serialNo (出库单号，唯一)
  ├── outboundTime
  ├── quantity
  ├── price (出库单价)
  ├── material_id (FK → Material, 非空)
  ├── department (领用部门)
  └── remark
```

## 五、关键设计要点总结

1. **库存字段**: 库存数量直接存储在 `Material.stockQuantity` 字段中，出入库时直接更新该字段，不通过记录聚合计算
2. **事务控制**: Service 层使用 `@Transactional` 确保库存更新和记录保存的原子性
3. **双重校验**: 出库时前端先做库存校验，后端再做一次兜底校验
4. **数据聚合**: 图表数据完全在前端通过 `computed` 和 `Array` 方法（`forEach`/`map`/`reduce`/`filter`/`sort`/`slice`）聚合，后端仅提供原始物资列表
5. **异常处理**: 后端业务异常通过 `RuntimeException` 抛出，由 `GlobalExceptionHandler` 统一包装返回
